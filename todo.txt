WHICH RELEASE A FRESH INSTALL STARTS ON
-------------------------------------------------------------------------------

- [ANY] index-v0.json publishes RomWBW 3.6.0 as `default: true` and both
releases as `stable`.  A fresh install still starts on 3.5.1, because
initialRomWBWVersion() falls back to the bundled ROM's release and
RomWBWIndex.preferred then keeps whatever is already in play.  Until build 65
that was forced: 3.5.1 was the only release this app had a ROM for.  It is not
forced any more - the ROM for any release is fetched and verified - so the
ordering is now a decision, and the code says so where it is made.
  Arguments both ways, and neither is obvious.  Following `default` is what the
index is FOR, it is how a new RomWBW version reaches people without a store
release, and a fresh install has to download disks anyway so the extra 512 KB
costs nothing.  Against: it moves every new user onto a release the app carries
no ROM for, so a first launch on a bad connection gets further from a booting
machine, and 3.6.0's NVRAM and disks are not 3.5.1's.
  Existing users are not affected either way - a stored choice wins over both.
Whoever decides this should also decide whether the bundled ROM should become
3.6.0 at the same time, which is a store release and a new ROM_ATTESTATION date.

    renames rather than re-downloads, so a migrated device keeps its v1.4.12
    bytes under the v0 name - and hd1k_combo is the one image of twenty whose

    hash there, and the exception stops applying the moment a device fetches the
    canonical image.  romwbw_disks' docs/FINDINGS.md section 10 has the byte
    ranges.
