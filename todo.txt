Needs a Mac
-----------

- [MAC] emu_host_file_get_read_name() answers truthfully now and R8 still cannot
  hear it, and that is a shape worth fixing rather than a wrong answer.  The
  backend records the resolved path (emu_host_file_load_named) and the getter
  returns it while HOST_FILE_READING.  But R8 prints its `Reading:` line between
  the open and the first read, and an open here only parks the request for the
  Swift layer's next main-queue turn - the guest is rewound on HBF_HOST_READ,
  not on the open - so at the moment R8 asks the state is still WAITING_READ and
  the honest answer is "".  Watched on the simulator at build 55 against an image
  whose R8 does call 0xEA: `R8 ESC.TXT` for a file stored as `esc.txt` printed
  `Reading: ESC.TXT`.  cpmdroid has the identical shape for the identical reason.

  The fix is settled and specified in WIP.md - read it before starting, because
  an earlier idea recorded there is wrong and named as wrong.  Resolve the name
  at OPEN time instead of at data time: make this port's open synchronous inside
  emu_host_file_open_read(), which is what the CLI and Windows backends already
  do.  No shared-core file changes; emu_io_ios.mm is port-local.  The duplicate
  case-insensitive scan gets DELETED from Swift rather than added to C++, so
  there is one resolver and not two that can drift.

  A second bug falls out of the same edit.  iOS's Documents volume is
  case-INsensitive, so Swift's fileExists fast path succeeds for a file stored
  as esc.txt when the CCP asked for ESC.TXT, and the path handed on carries the
  case the CCP invented rather than the case the file has - so even when the
  race lands the right way the answer is dishonest.  realpath() does not fix
  this; always scan and take the directory entry's own spelling.

  Testable here: run_core_suite compiles a .cc suite against the symlinked core
  and lets the test supply the backend, the way Tests/CoreKeyboardTests.cc
  already stubs the whole host-file API.  WIP.md also lists six traps that have
  each bitten this code before, and the manual check that closes the item.
